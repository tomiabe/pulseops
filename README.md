## About

PulseOps simulates a live industrial monitoring environment with:

- **6 machines** generating real-time sensor telemetry (temperature, pressure, vibration, efficiency, RPM)
- **Anomaly injection** with auto-remediation events
- **Alert management** with severity levels and acknowledgements
- **SPC control charts** with upper/lower control limits and target zones
- **Event timeline** merging alerts and plain-English insights
- **Machine detail views** with per-metric history

### What this is NOT

This is **not connected to real equipment**. All telemetry is procedurally generated by a Python simulator. No actual machines, sensors, or industrial systems are connected.

### What this IS useful for

- **Reference implementation** for real-time dashboards using WebSockets
- **Frontend patterns** for live-updating charts, alert lists, and status indicators
- **Backend patterns** for WebSocket broadcasting, state management, and simulated telemetry
- **Deployment blueprint** for FastAPI + React projects on Railway
- **Design reference** for dark-theme operations UIs inspired by Linear

## Getting Started

```bash
# Backend
pip install -r backend/requirements.txt
python -m uvicorn backend.main:app --reload

# Frontend (separate terminal)
cd frontend
npm install
npm run dev
```

The frontend dev server proxies `/api` and `/ws` to the backend at `localhost:8000`.

## Plugability

The simulator in `backend/simulator.py` is a self-contained module that can be:

- **Replaced** with a real data source (e.g., MQTT broker, OPC UA server, SCADA API, AWS SiteWise)
- **Extended** to support additional sensor types or machine profiles
- **Embedded** into larger industrial monitoring stacks as a data shim

The frontend expects a WebSocket JSON protocol — documented in the simulator's message types — making it straightforward to swap in any real-time backend.
